# Errandkite 项目提案

> 状态：草案 v0.1（2026-11-22）。本文按《KiteAI 第二期开发者参与指南》要求，在开发前写明目标用户、使用场景、KiteAI 关联点、核心功能、技术方案和验收标准。设计依据见 [REFERENCE_STUDY.md](REFERENCE_STUDY.md)。
>
> **全部功能只在 Kite 测试网运行，使用测试币 pieUSD，不涉及真实资金。** 未接通的能力在文中标"计划"。

## 1. 要解决的问题

AI agent 能写代码、查资料，但经常卡在只有真人能做、而且很小的事情上：

- 一个网站在另一个地区、另一种网络下能不能打开、能不能正常注册
- 两版设计、两个标题，哪个更好，给一句理由
- 一段文字读起来像不像机器写的
- 一个页面在手机上显示有没有问题

这些事一个人花一分钟就能做完，值几分到几毛钱。但现在 agent 没办法**自己**付这点钱给一个陌生人：传统支付需要账户、银行卡、最低金额和人工审批。x402 加上 Kite 测试网的小额即时结算，正好能做这件事。**没有小额即时付款，这个产品就不存在。**

## 2. 目标用户和使用场景

| 用户 | 场景 |
|---|---|
| **发布方：AI agent 和它的开发者** | agent 在执行任务时遇到需要真人判断的环节，调用 MCP 工具 `post_bounty` 发出悬赏，等答案回来后继续执行 |
| **回答方：Kite 社区成员、其他 builder** | 在网页上浏览悬赏，挑自己能答的，回答并留下 Kite 测试网地址，被采纳后收到 pieUSD |

第一批真实用户计划来自 Kite 社区和 OpenBuild 第二期参与者（用测试币）。所有使用数据如实公开，见第 9 节。

## 3. 同类项目

"AI 雇真人"在其他链上已经有项目：Wurk（Solana）、Vangrid（Base / Arc）、Human Pages（MCP）、TaskMarket（Base）、RentAHuman（2026-02 上线）、HackMoney 2026 项目 Hands for AI（Base 合约托管）。**在 Kite 上没有找到同类项目。**

公开报道里，记者实测 RentAHuman 时发现，真正由 AI 自主发出的悬赏很少，不少是人发的或推广。所以 Errandkite 的差异点放在：

1. **Kite 原生**：发布走 Kite 测试网 x402，放款和退款在 Kite 链上
2. **全程可查、来源如实**：每个悬赏从付款到放款或退款都有交易哈希和公开页面；每个悬赏标明是 agent 通过 MCP 发布还是人工测试，不混在一起统计
3. **对 agent 友好**：MCP 工具 + 结构化 JSON 答案，agent 能自己判断和采纳

## 4. 与 KiteAI 的关联点

| 关联点 | 位置（计划） | 如何验证 |
|---|---|---|
| 发布悬赏是 x402 付费请求，在 Kite 测试网 `eip155:2368` 用 pieUSD 结算，经 pieverse facilitator | `src/payment/`，复用官方 `kite.ts` | 未付费请求返回 402，解码 `PAYMENT-REQUIRED` 核对网络、资产、金额；付费后得到结算交易哈希，可在 testnet.kitescan.ai 查 |
| 采纳后平台钱包在 Kite 测试网向回答者转 pieUSD | `src/chain/payout.ts` | 放款交易哈希可在 kitescan 查到，金额与悬赏一致 |
| 超时无人回答，平台把 pieUSD 退回付款地址 | `src/chain/payout.ts`、定时任务 | 退款交易哈希可查 |
| 用 Kite Passport（`kpass`）作为付款的 agent | 端到端测试文档 | 记录 `kpass` 调用和对应交易哈希 |
| 登记到 `gokite-ai/kite-x402-services` 服务目录 | `service.yaml` | 提交的登记 PR |

## 5. 核心功能

### 5.1 悬赏的生命周期

```
               x402 付款成功            有人回答            agent 采纳            放款上链
 (发布请求) ──────────────▶ open ──────────▶ answered ──────────▶ accepting ──────────▶ paid
                              │                   │
                              │ 到期无人回答        │ 到期仍未采纳
                              ▼                   ▼
                          refunding ─────────▶ refunded（退款上链）
```

- 付款结算失败：不创建悬赏（或标记作废），不进入 `open`
- 一个悬赏可以收多个回答，agent 采纳其中一个；未被采纳的回答不付钱
- 到期时间由发布方设定，有上下限（计划：10 分钟到 72 小时）
- 平台手续费 v0.1 为 0

### 5.2 金额怎么定（变动金额 vs 固定价格）

官方模板一个接口只能定一个固定价格，但每个悬赏金额不同。`@x402/core` 2.32.0 提供 `DynamicPrice`，可以按每次请求计算价格，所以：

- 发布接口 `POST /v1/bounties?reward=0.10`：402 挑战里的金额 = 请求里的悬赏金额
- 金额有上下限（计划：0.01 到 1 pieUSD），超出范围直接返回 400，**不发 402，所以不会扣款**
- 参数校验放在付费中间件之前，所以格式错误的请求根本不会走到付款这一步
- 待 W1 验证：`DynamicPrice` 能否读到请求体。读不到的话，金额和必要参数放查询参数里

### 5.3 接口（计划）

| 接口 | 付费 | 谁能调 | 作用 |
|---|---|---|---|
| `POST /v1/bounties` | ✅ x402 | 任何付款方 | 发布悬赏，返回悬赏 ID、**管理令牌**、付款交易哈希 |
| `GET /api/bounties` | — | 公开 | 悬赏列表（分页、按状态筛选） |
| `GET /api/bounties/:id` | — | 公开 | 悬赏详情、回答（采纳前只显示数量）、资金流水 |
| `POST /api/bounties/:id/answers` | — | 公开，限流 | 提交回答 + 收款地址 |
| `GET /api/bounties/:id/answers` | — | 持管理令牌 | 发布方读取全部回答 |
| `POST /api/bounties/:id/accept` | — | 持管理令牌 | 采纳一个回答，触发放款 |
| `POST /api/bounties/:id/cancel` | — | 持管理令牌 | 无人回答时提前取消，触发退款 |
| `GET /api/stats` | — | 公开 | 使用统计（第 9 节） |
| `GET /healthz` | — | 公开 | 健康检查 |

**访问控制**：发布成功时返回一个随机管理令牌，数据库只存它的哈希。读取回答、采纳、取消都要带这个令牌；没有令牌只能看公开信息。

### 5.4 MCP 工具（计划）

`post_bounty`、`get_answers`、`accept_answer`、`cancel_bounty`。付款由 agent 自己的 x402 客户端完成（如 `kpass`）；MCP 工具负责发起请求、保存管理令牌、整理返回结果。

### 5.5 网页（计划）

悬赏列表、悬赏详情、回答表单、资金流水。每个页面处理**加载中、没有数据、出错**三种状态（指南要求）。不需要登录，也不需要连接钱包；回答时只需填写一个 Kite 测试网地址。

## 6. 技术方案

| 层 | 选型 | 理由 |
|---|---|---|
| 运行环境 | Cloudflare Workers（免费版） | 不休眠、自带 https、定时触发、D1 数据库 |
| Web 框架 | Hono | Workers 原生支持；kite-x402-hono 已证明 `@x402/hono` 能接 Kite |
| 付费 | `@x402/hono` + `@x402/evm`（`ExactEvmScheme`）+ `HTTPFacilitatorClient` | 与官方模板同一套 SDK |
| Kite 参数 | 官方模板 `kite.ts` **原样复用**，`NOTICE` 写明来源和上游版本 `893a275` | Apache-2.0 |
| 放款 / 退款 | `viem`：平台钱包签名 pieUSD 的 ERC-20 `transfer` | 签名在本地完成，等链上返回不计入 CPU 时间 |
| 数据库 | Cloudflare D1 | 托管资金的状态不能放内存（见参考研究结论 4） |
| 定时任务 | Workers Cron Triggers | 处理到期退款、每日自检 |
| 网页 | 由同一个 Worker 提供的静态页面 + 少量脚本 | 不额外引入前端框架 |
| 测试 | Vitest + `@cloudflare/vitest-pool-workers` | 在 Workers 运行环境里测 |

### 6.1 资金安全

- **托管**：v0.1 由平台钱包托管，只在测试网运行；公开托管余额和每一笔流水。链上托管合约放在 v0.1 之后
- **防重复放款**：状态变更用条件更新（`UPDATE … WHERE status = 'answered'`），只有一个请求能把状态推进到 `accepting`；放款交易哈希写库后才标 `paid`
- **放款失败**：保持 `accepting` 状态并记录错误，由定时任务重试；同一悬赏只允许一笔放款交易
- **账目一致**：任何时刻 托管余额 = 已收付款 − 已放款 − 已退款，每日自检核对链上余额
- **私钥**：只存在 Workers secret 里，不进代码、配置和日志
- **gas**：平台钱包需要测试网 KITE 付 gas，余额低于阈值时在 `/healthz` 和日志里报警

### 6.2 其他安全措施

- 回答内容做 HTML 转义，防 XSS；长度上限
- 收款地址校验格式和校验和
- 回答接口按 IP 和地址限流（状态存 D1，不存内存）
- 悬赏内容不允许包含收款地址以外的个人信息字段；网页注明"不要在回答里留个人信息"

## 7. 不做的事（v0.1）

- 不上主网，不处理真实资金。主网付钱给真人会涉及税务、身份核验等合规问题，要单独评估
- 不做声誉系统、争议仲裁、多人分账
- 不做登录和账户体系
- 不为了展示堆砌没有接入主流程的模块

## 8. 验收标准

1. 未付费调用发布接口返回 402；`PAYMENT-REQUIRED` 解码后 network = `eip155:2368`，asset = pieUSD 合约地址，金额 = 悬赏金额换算成 18 位小数的最小单位，精确相等
2. 用 `kpass` 付费发布一个悬赏，返回 200 + 悬赏 ID + 管理令牌 + 付款交易哈希，交易可在 testnet.kitescan.ai 查到
3. 采纳后，回答者地址收到等额 pieUSD，放款交易哈希可查
4. 到期无人回答，付款地址收到退款，退款交易哈希可查
5. 金额越界、参数缺失时返回 400，**不返回 402、不扣款**
6. 没有管理令牌或令牌错误时，读取回答、采纳、取消都返回 401/403
7. 并发采纳同一悬赏，只产生一笔放款交易（自动化测试）
8. 账目一致性测试通过；每日自检任务运行并留下记录
9. 网页的列表、详情、回答三个页面都处理加载中、空数据、出错状态，并和后端联调通过
10. 干净环境按 README 用 `npm install` + `npx wrangler dev` 在本地跑起来（含本地 D1），`npx wrangler deploy` 一条命令部署
11. CI：格式检查、类型检查、测试、构建、依赖审计
12. 文档齐全：README、`docs/ARCHITECTURE.md`、API 文档、测试与部署文档、`.dev.vars.example`、CONTRIBUTING、CHANGELOG、LICENSE、NOTICE
13. 向 `gokite-ai/kite-x402-services` 提交登记 PR（status: testnet），附付费证据

## 9. 如何衡量是否真的有人用

不预设需求，用公开数据说话。`/api/stats` 和 README 定期更新：

- 悬赏数，**按来源分开**：agent 通过 MCP 发布 / 人工测试
- 回答数、被采纳率、从发布到第一个回答的时间
- 放款、退款笔数和金额（测试币）
- 不同的发布方地址数、回答方地址数

如果数据显示需求很弱，会在项目记录里如实写明，并据此调整方向。

## 10. 风险

| 风险 | 应对 |
|---|---|
| 真实需求弱 | 第 9 节的公开统计；按来源分开，不用人工测试冒充 agent 使用 |
| 没人回答（冷启动） | 先在 Kite 社区、OpenBuild 参与者群邀请；悬赏设计成一分钟能完成的小问题 |
| 乱答、刷单、一人多号 | 发布方自己决定采纳，不采纳不付钱；限流；v0.1 不做声誉系统，写进已知限制 |
| Workers 免费版每次请求只有 10ms CPU | W1 实测签名和 x402 验证的 CPU 时间；不够就换 Koyeb 免费版或 Fly.io |
| `@x402/evm` / `viem` 在 Workers 运行环境的兼容性 | W1 实测；需要时开 `nodejs_compat` |
| `DynamicPrice` 能否读到请求体 | W1 实测；不行就把金额放查询参数 |
| passport-skills 文档写开发环境在 Arc 测试网结算，与 Kite 测试网的关系未理清 | W1 实测 `kpass` 能否给 Kite 测试网接口付款；不行就调整验收标准 2 |
| 平台钱包托管的资金安全 | 只在测试网、私钥放 secret、公开余额、每日对账；之后改链上合约 |
